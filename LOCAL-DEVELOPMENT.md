# Локальный запуск

Для ежедневной работы дважды щёлкните `start-local.bat` в корне проекта.
Лаунчер поднимает весь контур: PostgreSQL, API, AI-сервис и 3D-виджет.

## Что требуется на компьютере

- Node.js с npm;
- Docker Desktop;
- Python 3.11 или 3.12.

Docker Desktop лаунчер попробует запустить сам. При первом запуске он также
создаст локальное Python-окружение `.venv`, установит зависимости, подготовит
Prisma и схему PostgreSQL. Первый запуск может быть долгим из-за PyTorch и весов
AI-моделей; последующие запуски используют уже готовое окружение.

## Порты без конфликтов

Сначала используются стандартные порты проекта:

- API — `3000`;
- AI — `5000`;
- 3D-виджет — `5173`;
- PostgreSQL — `5432`.

Если порт занят другим локальным проектом, лаунчер выбирает свободный порт из
резервного диапазона и передаёт его всем зависимым сервисам. Выбор сохраняется в
`.flat-local-ports.json`, поэтому адреса остаются стабильными, пока это возможно.
Актуальные ссылки всегда печатаются в окне запуска.

Если контейнер PostgreSQL остался работать после прошлого запуска, лаунчер сам
остановит только контейнер этого проекта перед проверкой и повторно займёт его
сохранённый порт. Поэтому собственная база проекта не воспринимается как
сторонний конфликт.

Повторный запуск не создаёт второй экземпляр: используется файл блокировки
`.flat-local.lock`. Если проект уже работает, повторный двойной щелчок покажет
текущие адреса и откроет 3D-виджет в браузере.

## Остановка

Нажмите `Ctrl+C` в окне запуска. Приложения остановятся; контейнер PostgreSQL
останется запущенным для быстрого следующего старта, а данные сохранятся в Docker
volume. При необходимости остановить базу отдельно:

```powershell
docker compose -p flat-local -f infra/docker-compose.yml stop postgres
```

Проверить, какие порты выбрал бы лаунчер, ничего не запуская:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1 -PlanOnly
```
